# 重建后检查与自动化状态

当前重建集群后无需手动介入配置，均已纳入自动化交付与配置管理。

## 节点标签（已全自动化）

GPU 与存储标签已全部由 Ansible 声明式管理：`ansible/inventory/host_vars/homelab-1.yaml` 的 `k3s_node_labels` 由 `group_vars/workers` 渲染进 k3s 节点配置，节点重建后 `install-k3s` 自动恢复，无需人工执行 `kubectl label`（包括 `nvidia.com/gpu.present`、`intel.feature.node.kubernetes.io/gpu` 与 `node.longhorn.io/create-default-disk`）。

重建后验证命令：

```bash
kubectl get nodes -L nvidia.com/gpu.present,intel.feature.node.kubernetes.io/gpu,node.longhorn.io/create-default-disk
```

## Multus 网络缓存

Multus CNI 配置由 Flux 交付的 Multus chart（`k8s/infra/common/network/multus/app/`）在节点生成。`delete-k3s` 通过 `ansible/playbooks/tasks/remove-multus.yaml` 清理 `/etc/cni/net.d/*multus*` 旧配置，重建后无需手动清理
